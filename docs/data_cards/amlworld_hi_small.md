## 2. Licence and redistribution

**The data and the code carry different licences, and this distinction is load-bearing
for Phase 14.**

| Artifact | Licence |
|---|---|
| AMLworld **data** | **CDLA-Sharing-1.0** ([text](https://cdla.dev/sharing-1-0/)) |
| `IBM/AML-Data` **repository code** | Apache-2.0 |
| This repository | Apache-2.0 |

The IBM/AML-Data README states it explicitly: *"Although this Github repository is under
the Apache-2.0 license, the actual data is released under the CDLA-Sharing-1.0 license."*

### What CDLA-Sharing-1.0 obliges (verified 2026-08-01)

- **Redistribution is permitted.** The licence grants a worldwide, non-exclusive,
  irrevocable right to Use and Publish Data.
- **Share-alike on data.** If we publish the Data or Enhanced Data (data we have modified
  or added to), it must go out under an unmodified form of CDLA-Sharing-1.0, with the
  agreement text included and attribution to the Data Provider preserved.
- **Changes must be marked.** Published modifications must carry prominent notices saying
  they were changed.
- **No added restrictions.** We may not impose commercial-use, platform or field-of-use
  restrictions downstream.
- **§3.5 — Results are exempt.** *"This Agreement imposes no obligations or restrictions
  on Your Use or Publication of Results."* Results are outputs of computational use,
  excluding more than de-minimis portions of the original Data.

### Consequences for this project

1. **Trained models, generated SAR narratives, and evaluation metrics are Results**, so
   the share-alike obligation does **not** reach them. Phase 14 can release model weights
   and `RESULTS.md` under Apache-2.0.
2. **Anything that embeds more than a de-minimis portion of AMLworld rows is Data or
   Enhanced Data** and must ship under CDLA-Sharing-1.0 with attribution and change
   notices. This includes `data/interim/` Parquet files and the Bronze corpus if it quotes
   transaction rows. Phase 14 must not sweep these into the Apache-2.0 bundle.
3. **The committed test fixture is already a redistribution.**
   `tests/fixtures/amlworld/` holds a 500-row slice, so `tests/fixtures/NOTICE` carries
   the attribution and the required record of changes. That file is an obligation, not
   documentation — do not delete it.

*Open item:* the Kaggle page's own licence field was not machine-readable at the time of
writing. The CDLA-Sharing-1.0 designation is taken from the authors' own repository, which
is the authoritative statement. If Kaggle states something narrower, the narrower terms

## 4. Schema

### `HI-Small_Trans.csv`

The header is asserted against the file, never recalled — `assert_header()` aborts the
load on any deviation, because column *positions* are load-bearing (see the duplicate
below).

```
Timestamp,From Bank,Account,To Bank,Account,Amount Received,Receiving Currency,
Amount Paid,Payment Currency,Payment Format,Is Laundering
```

| # | Source column | Our name | Type | Semantics |
|---|---|---|---|---|
| 0 | `Timestamp` | `timestamp` | Datetime(us) | Local wall-clock, minute resolution, no timezone. Format `%Y/%m/%d %H:%M` |
| 1 | `From Bank` | `src_bank` | Utf8 | Originating bank code. **Zero-padded** |
| 2 | `Account` | `src_account` | Utf8 | Originating account, opaque hex. Unique only *within* a bank |
| 3 | `To Bank` | `dst_bank` | Utf8 | Beneficiary bank code |
| 4 | `Account` **(duplicate)** | `dst_account` | Utf8 | Beneficiary account |
| 5 | `Amount Received` | `amount_received` | Float64 | In `receiving_currency` |
| 6 | `Receiving Currency` | `receiving_currency` | Utf8 | One of 15 |
| 7 | `Amount Paid` | `amount_paid` | Float64 | In `payment_currency` |
| 8 | `Payment Currency` | `payment_currency` | Utf8 | One of 15 |
| 9 | `Payment Format` | `payment_format` | Utf8 | One of 7 |
| 10 | `Is Laundering` | `is_laundering` | Boolean | Binary flag, 0/1 in source |

**Schema surprises, and how each is handled:**

1. **`Account` appears twice.** Polars silently renames the second to
   `Account_duplicated_0`; pandas would produce `Account.1`. Neither rename is part of any
   contract. The loader renames **positionally** after asserting the raw header, so it
   never depends on a de-duplication rule it does not control.
2. **Bank and account codes are zero-padded strings.** Read as integers, bank `010` would
   collide with bank `10`. Every identifier is kept Utf8.
3. **Amounts are not uniformly two-decimal.** 148,151 receiving amounts and 146,066 paid
   amounts (the Bitcoin rows) carry **six** decimals. This matters because the natural
   key used to join the patterns file to the CSV includes the amount: a key rebuilt by
   re-formatting a parsed float cannot be faithful, since `0.370000` and `0.37` are the
   same number and different text. The loader therefore builds `transaction_key` from the
   **source text**, before any cast, and `require_transaction_keys()` refuses to
   reconstruct it. Getting this wrong costs exactly one transaction — see §6.

### `HI-Small_Patterns.txt`

The **only** source of typology ground truth. Grammar:

```
BEGIN LAUNDERING ATTEMPT - <TYPOLOGY>[:  <detail>]
<CSV row, same 11 columns, no header>
...
END LAUNDERING ATTEMPT - <TYPOLOGY>
<blank line>
```

Parsed by a state machine (`_StreamState`) that rejects nested BEGINs, unmatched or
mismatched ENDs, empty streams, rows outside a stream, unknown typologies, wrong field
counts, and malformed delimiters — the last so a typo'd delimiter cannot be silently read
as a transaction. Output is tidy: one row per `(pattern_id, typology, typology_detail,
transaction_key, position_in_stream)` plus the eleven transaction fields.

A transaction may legitimately appear in more than one stream, so `transaction_key` is not
unique in this table.

## 5. Availability mask

Invariant 4: nothing may assert a fact that does not exist for this substrate.

| Field | Value | Justification |
|---|---|---|
| `absolute_timestamps` | **true** | Real wall-clock datetimes, 2022-09-01 to 2022-09-18 |
| `fine_temporal_resolution` | **true** | Minute-level, observed (15,018 distinct timestamps) |
| `monetary_amounts` | **true** | Both paid and received amounts |
| `currencies` | **true** | 15 named currencies |
| `institution_identity` | **true** | Bank code on both endpoints |
| `entity_types` | **false** | **Corrected in Phase 1.** The schema carries a bank code and nothing else about an account. There is no business-type column, so no "mixer", "exchange" or "merchant" label can ever be asserted. The Phase 0 config claimed `true`; it was written before any data was on disk |
| `node_labels` | **true** | Per-transaction laundering flag, aggregable to accounts |
| `typology_ground_truth` | **true** | Eight typologies, plus `unclassified` |
| `semantic_node_features` | **false** | AMLworld ships **no node table at all**. Our node attributes are aggregates we derive from the transactions. This flag governs *supplied* feature columns with published meanings; it does not forbid statements about derived aggregates such as degree or total sent, which are licensed by `monetary_amounts` and the edge data |

The eight-key mask in `configs/data/amlworld.yaml` is the projection of this one via
`AvailabilityMask.to_config_mask()`; `tests/unit/test_availability.py` asserts they agree,
so the two vocabularies cannot drift apart.

## 6. Observed versus published statistics

Ingest run 2026-08-01 on the checksum-verified release, complete dataset, no subsetting.

### Headline counts — exact match

| Quantity | Published | Observed | Match |
|---|---:|---:|:--:|
| Vertices (accounts) | 515,088 | **515,088** | ✅ |
| Edges (transactions) | 5,078,345 | **5,078,345** | ✅ |

**The node count only reconciles under a composite key.** Keying nodes on the account
identifier alone yields **515,080**; keying on `"<bank>|<account>"` yields **515,088**.
Eight account identifiers genuinely collide across banks. The composite key is therefore
the correct one, and the published figure confirms it — this is the exact discrepancy the
phase brief warned about, and it resolves in favour of `bank|account`. That keying is
asserted by `test_node_count_requires_the_bank_account_composite_key`.

### Typology distribution — exact match on all nine

Counts are of **transactions inside pattern streams**, not of streams. The distinction
matters: HI-Small has **370 streams** covering **3,209 transactions**.

| Typology | Published | Observed | Match | Streams |
|---|---:|---:|:--:|---:|
| Fan-out | 342 | **342** | ✅ | 48 |
| Fan-in | 318 | **318** | ✅ | 40 |
| Gather-scatter | 716 | **716** | ✅ | 51 |
| Scatter-gather | 626 | **626** | ✅ | 44 |
| Cycle | 287 | **287** | ✅ | 54 |
| Random | 191 | **191** | ✅ | 41 |
| Bipartite | 263 | **263** | ✅ | 49 |
| Stack | 466 | **466** | ✅ | 43 |
| **Not classified** | 1,968 | **1,968** | ✅ | — |
| *Patterned total* | *3,209* | *3,209* | ✅ | *370* |

The brief offered these as approximate targets. They are exact.

`unclassified` is not a null: it is the 1,968 transactions flagged `Is Laundering` that
appear in **no** pattern stream. It is a first-class member of `TYPOLOGY_VOCABULARY`, so a
narrative can say "flagged, but matching no known structural pattern" rather than invent
one. It is also arithmetically forced: 3,209 patterned + 1,968 unclassified = **5,177**
laundering transactions, which is exactly the flag count in the CSV.

**This reconciliation is how a real bug was caught.** The first implementation rebuilt the
join key by formatting the parsed amount to two decimals, and produced `unclassified` =
1,969. One Bitcoin transaction (`0.370287`, six decimals) failed to join. Every other
typology matched, so only the arithmetic identity above exposed it.

## 7. Known limitations

1. **Synthetic.** Realistic by construction, not real. Distributional claims about actual
   financial crime cannot be supported from this substrate — which is why Elliptic2 exists
   in this project.
2. **Extreme class imbalance.** 1 in 981. Any case-extraction or training scheme in later
   phases has to address this explicitly; accuracy is meaningless here.
3. **Extreme degree skew.** Out-degree max 168,672 against a median of 2. A handful of
   hub accounts will dominate any naive neighbourhood sampling, and a GAT that attends
   over full neighbourhoods will not fit them in memory.
4. **Self-loops are 11.6% of edges.** More numerous than the 481,056 `Reinvestment` rows,
   so they are not solely a reinvestment artefact. Phase 7 must decide deliberately
   whether the encoder keeps them.
5. **The graph is a multigraph.** 561,575 node pairs carry more than one transaction, up
   to 89. Any adjacency-matrix formulation would silently collapse repeated transfers.
6. **Fragmented.** 114,139 weakly-connected components, median size 1, with 72% of nodes
   in one giant component. Case extraction in Phase 2 must not assume connectivity.
7. **No entity types.** See the availability mask. No account can be called a mixer, an
   exchange or a merchant.
8. **Two amount columns, two currencies.** `amount_received` and `amount_paid` differ for
   cross-currency transfers. A narrative must say which it means; conflating them is a
   faithfulness error the Phase 3 fact layer must be able to catch.
9. **Short window.** 17.7 days. Any "typical monthly behaviour" claim is unsupported, and
   the Phase 2 temporal split has very little room.
10. **Amounts span twelve orders of magnitude**, from 10⁻⁶ to 1.05 × 10¹². Raw amounts as
    model features will need transforming.

## 8. Our preprocessing

`scripts/01_ingest.py` → `data/interim/amlworld_hi_small/`:

1. **Verify** both files against the pinned SHA-256 digests. Abort on mismatch.
2. **Assert** the CSV header equals `EXPECTED_HEADER` exactly. Abort on mismatch.
3. **Load** all 5,078,345 rows as Utf8, build `transaction_key` from the source text, then
   cast timestamp/amounts/flag. Identifiers stay Utf8.
4. **Parse** the patterns file into a tidy table via the state machine.
5. **Attach typologies** by left-joining on `transaction_key`; laundering rows matching no
   stream become `unclassified`. Where a transaction is in several streams, the first by
   `pattern_id` wins, so the row count is preserved.
6. **Build the account graph**: nodes keyed `"<bank>|<account>"`, with derived aggregates
   (`in_degree`, `out_degree`, `degree`, `total_received`, `total_sent`, `first_seen`,
   `last_seen`, `bank`). Edges carry all transaction attributes plus `typology` and
   `pattern_id`.
7. **Assert** the node/edge counts and all nine typology counts against the published
   figures. **Abort on any disagreement** (`data.verify_published: true`).
8. **Validate** referential integrity: every edge endpoint exists in the node table.
9. **Compute** the full statistics record.
10. **Write** `nodes.parquet` (10.0 MB), `edges.parquet` (172 MB), `canonical.json`,
    `statistics.json` and `manifest.json` with a SHA-256 per artifact. All writes atomic.

No sampling, no filtering, no deduplication. Self-loops and multi-edges are **kept** —
they are real properties of the substrate, and removing them here would silently change
every downstream statistic. Total runtime ≈ 14 s.

`ingest.n_rows` subsets for smoke runs; doing so records `subsetted_n_rows` and
`is_complete_dataset: false` in the manifest and disables the published-statistic check.
